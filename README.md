# Thesis Writing

面向人文社科论文的中文写作方法库，覆盖研究问题收敛、范文结构与语言分析、文献核验、正文写作、交叉审查和Word交付。重点是把理论、证据和作者自己的表达连起来，减少空泛套话、重复解释和机械过渡。

本仓库只提供通用方法和空白模板。具体选题、作者资料、未发表正文、授权阅读的毕业论文以及阅读摘录，应保存在独立的私人项目中。

## 从哪里开始

1. 阅读[完整工作流程](docs/workflow.md)，确定本阶段的输入与交付物。
2. 用[范文结构与语言学习](docs/reference-learning.md)拆解授权资料，先弄清其论证功能，再提炼适用于当前研究的原则。
3. 依据[自然准确的学术中文](docs/writing-style.md)写作和清稿，把作者自己的修订文本作为主要语言基准。
4. 依[文献与引注规范](docs/citations.md)核对文献实际支持的观点，再用[审查与Word交付](docs/review-and-word.md)验收。
5. 每次分享文件或推送仓库前执行[隐私发布规则](docs/privacy.md)。

## 如何学习论文的结构与用语

先逐页阅读文字，再检查目录、章首段、概念定义、理论进入案例的位置和结语。记录“每节在回答什么、用什么证据、怎样从来源观点推进到作者判断”，而不仅是记下章数。版式另作视觉检查：正文注码、页下注、书目编号和页面布局分别确认。PDF观察到的字号与间距只能作为参照，最终服从学校规范。

语言学习从作者自己的修改稿开始：比较修改前后哪些句子被保留、删除或改写，归纳段落节奏、术语选择、转述习惯和限定方式。借鉴范文的论证方法，不复制其辨识性句子，也不默认其强评价和引文均正确。

## 如何减少机械化表达

将“具有重要意义”改为具体研究问题；将“提供参考”展开为实际采用的概念或判断；将作者名单串联改为观点之间的比较。删去重复的自我说明、模板过渡和面向协作者的提示，把检索状态与待办保存在私人工作记录中。保留确实约束结论的范围说明，清稿后再核事实，避免把句子改流畅的同时扩大结论。

本方法以准确、清楚、有论证作用为目标，不以检测分数作为质量证明，不承诺任何“AI率”。学术引用与所需的工具使用说明仍按学校要求处理。

## 文件目录

- `docs/`：方法说明、证据要求、审查与隐私规则。
- `templates/`：研究问题卡、范文分析表、文献证据卡和修订记录的空白模板。
- `AGENTS.md`：协作者在本方法库中的操作范围。

本项目是方法文档库，不附送已配置的模型、数据库权限或自动Word服务。可选择使用研究工作流技能、Pandoc、python-docx及Word/LibreOffice；工具是否安装和可用应在实际写作项目中核实。
